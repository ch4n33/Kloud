# MinIO legacy CA projection

This records the one-time MinIO application trust-store exception authorized on 2026-10-22. The filtered bundle was taken from the currently deployed `docker.io/minio/minio@sha256:14cea493d9a34af32f524e538b8346cf79f3321eff8e708c1e2960462bd8936e` image (`RELEASE.2025-09-07T16-13-09Z`). Its original 142-root store contained emSign ECC Root CA - G3 once; AAA Certificate Services was already absent. The projection removes only that emSign fingerprint, adds no roots, and leaves 141 roots. `projection.json` records the source digest and bundle hash.

The deployment pins the same upstream multi-architecture index and uses `IfNotPresent` so the NAS can start from the exact cached amd64 image. A derived MinIO image was not produced because the original image/build inputs were unavailable from Docker Hub and Quay, and verified ARM64 build inputs could not be obtained. Do not replace this digest or claim a new architecture variant without verifying the vendor image and its per-platform inputs.

The NAS keeps a local OCI archive of the cached amd64 image at `/home/ch4n33/server-data/security-backups/2026-10-22/minio-14cea493d9a34af32f524e538b8346cf79f3321eff8e708c1e2960462bd8936e-linux-amd64.oci.tar` (SHA-256 `441dec6fd0a194262990a127f7cd6f4d58a476126fd7d0f1a92c3fa771dd8aca`). This archive covers only the NAS's `linux/amd64` image; it is not a published or multi-architecture replacement. If both the NAS cache and this archive are lost, the pinned image may be unavailable for a restart while the vendor source remains inaccessible.

`cluster/apps/minio/ca-configmap.yaml` is the desired ConfigMap. The Deployment mounts its `ca-certificates.crt` key read-only at `/etc/ssl/kloud-ca` and sets `SSL_CERT_FILE` to `/etc/ssl/kloud-ca/ca-certificates.crt` and `SSL_CERT_DIR` to `/etc/ssl/kloud-ca`. Runtime validation confirmed the mounted bundle hash, MinIO version, HTTP 200 for both health endpoints, GitHub trust, and certificate-verification failure for both distrusted test chains.
